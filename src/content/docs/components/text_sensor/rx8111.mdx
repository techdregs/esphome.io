title: "RX8111 Event Timestamp"

The `rx8111` text sensor publishes timestamps captured by the EVIN input of an
[RX8111 real-time clock](/components/time/rx8111/). Configure that time component first.

```yaml
text_sensor:
  - platform: rx8111
    name: "Event Timestamp"
```

## Configuration Variables

- **rx8111_id** (*Optional*, [ID](/guides/configuration-types/#id)): The RX8111 time component. Required when
  more than one RX8111 is configured. Only one timestamp text sensor is allowed per clock.
- **timestamp_record_mode** (*Optional*, string): Timestamp storage mode. Defaults to `latest`.
  - `latest`: Publish the latest captured record. A new event replaces the previous record.
  - `stop_when_full`: Store up to eight records; capture stops updating the buffer when it is full.
  - `overwrite`: Store the latest eight records, replacing the oldest when full.
- All other options from [Text Sensor](/components/text_sensor/).

## Capture And Publication

The text sensor enables EVIN capture independently of `event_enabled`, which controls the event interrupt and
`on_event` automation. Configure `event_level`, `evin_filter`, and `evin_pull` on the time component to match the
connected signal. With no explicit settings, capture uses an active-low input, no filter, and no internal pull.
The RTC must contain trusted UTC time; timestamp capture does not set or synchronize its calendar.

States use UTC ISO 8601 format, for example `2026-10-24T12:34:56.999Z`, regardless of the time component's timezone.
Fractional seconds are truncated to milliseconds. Invalid BCD, impossible dates, and records whose captured oscillator-stop
flag is set are skipped without replacing the last valid state. The supported calendar years are 2019–2099.

Records are checked using the time component's `event_poll_interval` (default `1s`, minimum `500ms`), even when
`update_interval: never` disables periodic calendar reads. No separate timestamp polling loop is created.

At startup, retained records are read using their previous storage format before the requested mode is applied.
In buffered modes, records are published oldest first, then the RAM pointer is cleared so capture can resume.
The entity state holds the last valid record; use `on_value` to process each record. Records arriving faster than
polling can be lost once storage is full, depending on the selected mode. Capture is briefly paused while records
are read and the pointer is cleared. In `latest` mode, polls of an unchanged record do not pause capture;
new or changed records are read again with capture paused. Events during a pause are not captured.

Publication does **not** clear EVF or release `/INT`. Use `rx8111.clear_event_flag` explicitly after handling an
event if acknowledgement is needed. In `latest` mode, an unchanged record is not published again until EVF is
acknowledged; a changed record is published even while EVF remains set. Buffered records are read even if EVF
has already been cleared. Capture restoration is attempted before text-sensor callbacks run. Staged records
are still published if restoration fails, and a later poll retries restoration.

I²C failures set a warning and are retried by the existing event polling or bounded startup retry mechanism.
Buffered records may be delivered again after a failed pointer clear. If restoring capture fails, a later poll
retries it. When no records have been published, the entity has no state.
